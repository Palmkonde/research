# scikit-learn User Guide, "3.3. Tuning the decision threshold for class prediction" (1.9.1)

Supports: classification splits into a statistical problem (predicting class probabilities) and a decision problem (taking action on them); `predict_proba` returns conditional probability estimates $P(y \mid X)$ and `decision_function` returns decision scores; binary `predict` uses hard-coded cut-offs, positive when $P(y \mid X)$ is greater than 0.5 or the decision score is greater than 0, which "are most certainly not ideal for most use cases"; in the tumor-detection example a missed cancer costs far more than further tests, so predicting positive well below 0.5 may be better (introduction); `TunedThresholdClassifierCV` post-tunes the threshold after training using internal cross-validation, choosing the threshold that maximizes a given metric; tuning leaves `predict_proba`, and so the ROC and PR curves, unchanged while changing the class predictions, with a tuned threshold around 0.02 in the insurance example (Section 3.3.1); the default metric is balanced accuracy, and one should choose a meaningful metric for the use case and the right `pos_label` (Section 3.3.1.1); by default 5-fold stratified cross-validation; "You should never use the same data for training the classifier and tuning the decision threshold due to the risk of overfitting", and `cv="prefit"` is only for an already trained classifier with a new validation set (Section 3.3.1.2); plotting metric values across thresholds is useful when more than one metric matters, and the `metric_at_thresholds` function computes a metric at each unique score threshold for such a plot (Section 3.3.1.3); `FixedThresholdClassifier` sets the threshold manually (Section 3.3.1.4).
